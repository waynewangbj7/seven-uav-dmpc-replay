# 设计思路、实现过程和修正记录

## 从论文 Case 1 到闭环仿真

目标是把七机异构角色编队做成可以逐阶段核对的仿真。先核对原 Case 1 的角色事件和槽位分配，再检查飞行模型能否实际跟踪指令，最后加入园区、逐机避障和起降。论文的角色协调和编队几何来自 Zhao 等的工作。工程实现使用 Python、CasADi/IPOPT 和 S6 槽位合并规则。 [论文原文](https://doi.org/10.1016/j.cja.2021.01.014)

旧版 RViz 从离线轨迹和事件驱动画面。Gazebo 版使用物理仿真的里程计计算下一周期指令，七个命名空间经 `ros_gz_bridge` 独立交换数据。每架机的高层速度指令转换至机体系，由 Gazebo 中的 X3 速度控制和旋翼动力学执行。起飞、道路进场、绕箱和着陆分别使用对应的控制阶段。

```mermaid
flowchart LR
    odom["Gazebo 七机里程计"] --> bridge["ros_gz_bridge"]
    bridge --> phase["任务阶段与 Case 1 角色协调"]
    phase --> cmd["逐机速度与航向指令"]
    cmd --> model["X3 速度控制与旋翼动力学"]
    model --> odom
```

## 阶段进展

| 阶段 | 设计与验证 |
|---|---|
| 离线复现和 RViz | 校对角色事件、槽位及最近机对，加入轨迹、城市外观和回放面板。 |
| X3 单机 | 建立 `/x3/odom` 和 `/x3/cmd_vel`，先完成 1.50 m 定高，再验证 2 m 定点移动和稳定停留。 |
| 小规模到七机 | 用两机检查相对位置跟踪和到点刹停，再以三机、五机和七机逐步验证空场控制。对应 CSV 位于 [阶段记录](../results/stages/)。 |
| 七机 Case 1 空场 | 空间按 1:100 缩放，仿真时间相对 Case 1 时间扩展 3 倍。标称 90 m/s 对应 Gazebo 0.30 m/s，200 m 槽位对应 2.00 m。用实际里程计触发事件并核对最终槽位。 |
| 单箱避障 | 先验证整队绕箱的净距，再改成按来向只让受影响飞机偏出和归队。 |
| 自然场景和起降 | 用起飞区、树带、道路、门岗和厂房连接空场与园区。七机升到 1.50 m 后横移约 8.6 m 到道路上空，再进入 Case 1。末段加七个落地标记，经减速、悬停、缓降后停稳。 |
| 冻结与对照 | 对同一基线做四轮连续复跑，保存 SHA-256 清单、轨迹和带机号的求解回退。四个单箱对比场景分别验证箱体位置、绕行对象和净距。 |
| 双箱定稿 | 让中间航线的 UAV-2、UAV-6 先绕一号箱并归队，随后 UAV-7 绕二号箱。延伸园区道路和着陆区，在同一 Gazebo 世界从起飞飞到停稳。 |

## 遇到的问题与修正

| 问题与现象 | 修正 | 验证 |
|---|---|---|
| RViz 只有网格，控制面板已经能播放 | 检查固定坐标系和 MarkerArray 显示，使用随编队的视角。 | 旧 [RViz 回放说明](../../README.md) 有已验证的启动和拓扑事件跳转方法。 |
| 单机前段高度波动，定点测试有刹停超调 | 把起飞、定高、定点跟踪和稳定停留分开检查，用速度阶跃记录评估 X3 的响应。 | 保存单机定高、2 m 定点、速度阶跃和两机刹停 CSV。 |
| 第一次 Case 1 闭环出现错误机对和额外事件 | 按观察到的 X3 稳态速度偏差用约 0.92 的增益换算，加入入场前加速，保留原比例和角色触发逻辑。 | 五次事件类型、机对和顺序对上离线基线，最终 14 条有向槽位分配一致。 |
| 连通后槽位误差仍大，重组段求解偶发回退 | 用采样轨迹分别统计首次连通、最大槽位偏差和最终间距。在冻结版日志中补记回退机号、角色和 IPOPT 状态。 | 连通后的瞬态和末段收敛可分开复算。四轮记录到 19 次达到迭代上限的单机回退。 |
| 绕箱时七架一起平移，动作过于刚性 | 将横移局部化。只有与箱体影响区相交的名义航线触发平滑偏移，各机按到达位置依次进入，再回到各自航线。 | A 与 B 中绕行对象会随箱体横向位置变化，C 则验证了净距随位置变化。 |
| 园区版从 Case 1 末态开场，缺失形成过程 | 在同一世界串联起飞、道路入口、原 Case 1、避障和下降，按真实里程计衔接。 | 完整日志包含 3/7、5/7、7/7 连通状态和七机接地记录。 |
| 方形树冠与分离山丘显得生硬，园区前较空 | 使用道路、树带和连续缓坡连接草地与园区，增加道边阴影和落地标记。展示几何与箱体、厂房碰撞几何分别配置。 | 进场和绕箱实景可在 [媒体目录](../media/) 查阅。 |
| WSLg 默认曾落到 `llvmpipe`，并出现 Qt/抗锯齿告警 | 用 `glxinfo -B` 和 Ogre 日志确认实际渲染设备，对单次启动指定 D3D12 的 NVIDIA 适配器，复跑串行执行。 | 四轮冻结复跑的日志确认使用 RTX 2050。有界面时的渲染与无界面时的物理复跑可分别检查。 |
| 早期场景依赖编写机器上的模型路径 | 发布入口将场景的相对资源名绑定到当前检出目录，X3 物理模型从指定版本的 Fuel 缓存生成。 | 发布版从独立的 Linux 路径跑完了无界面任务。该目录的首次 GUI 启动遇到 WSLg OpenGL 上下文错误，实景图采用原工作环境的完整 GUI 验证。见[发布验证记录](../results/release-validation.json)。 |

## 代码入口

- `case1/run_case1_full.py` 串起道路进场、Case 1、绕箱和着陆。
- `case1/run_case1_gazebo.py` 读取里程计，以实测状态更新编队并记录角色事件和求解回退。
- `case1/engineering_coordination.py` 维护角色、连接与槽位规则，`casadi_backend.py` 求解单机预测控制。
- `case1/run_avoidance.py` 从已知障碍地图分配受影响的飞机，生成分段平滑横移和回位参考。
- `case1/case1_mission_stages.py` 处理垂直起飞、道路转移、着陆悬停和降落。
- `scenes/` 保存五个 SDF 模板及对应 JSON 地图。SDF 用于 Gazebo，JSON 提供控制器所用的障碍坐标和停机位。
